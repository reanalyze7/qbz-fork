# Refactor plans — split every file >130 lines

Generated by ~40 parallel research agents on branch `refactor/split-files-130-lines`.
Each agent ONLY writes markdown plans here — no source code was touched.

## Rule being enforced (from the project owner's global CLAUDE.md)

1. 130 lines max per file/script.
2. Tests at each change (pytest or equivalent — here, `cargo test` / existing
   Slint compile checks), green before considering it done.
3. Clean folders: separate by responsibility — pure computation ↔ I/O ↔
   rendering. One package per domain, one README.md per package explaining
   the WHY of each module.

## How to apply

For each oversized file, the plan below proposes:
- How to split it into cohesive modules (pure/IO/render pattern where it
  applies — many files here are Rust business logic or `.slint` UI, so the
  split is usually "by responsibility/domain" rather than literally
  pure/IO/render).
- Which module re-exports the public API from a `mod.rs` (Rust) or stays a
  single import surface (Slint), so existing importers/callers don't break.
- A note on what to verify (compiles + tests green + smoke-test importers)
  before considering a file's split done.

## File naming

One markdown file per source file, mirroring its path with `/` -> `__`,
e.g. `crates/qbz/src/main.rs` -> `refactor-plans/crates__qbz__src__main.rs.md`.
